Modelos y Patrones de Arquitectura Web

Página web donde se conceptualizan y comparan las diferentes estructuras y modelos clave para el desarrollo web actual, organizada mediante una cuadrícula adaptable con CSS Grid.

Centralizado

Arquitectura Monolítica

Toda la aplicación es una sola unidad desarrollada y lanzada una sola vez. Todo el backend y frontend están juntos en un mismo código fuente y corren en un solo servidor.

  • Ventaja: Menor complejidad inicial para programar y probar.
  • Desafío: Las partes están tan pegadas que si una falla, puede tumbar toda la página.
Ejemplo: Blogs personales, portafolios web o tiendas pequeñas
Distribuido

Microservicios

Divide el backend en varios servicios pequeños e independientes que se comunican por HTTP. Esto permite actualizar o arreglar una función sin tener que reinstalar toda la aplicación desde cero.

  • Ventaja: Permite modificar o mejorar un servicio sin tocar el resto del sistema.
  • Desafío: Es más difícil monitorear y conectar tantos servicios por red.
Ejemplo: Plataformas grandes como Netflix, Uber o Amazon
Estructural

Arquitectura de 3 Capas

Es una arquitectura que separa el desarrollo en tres niveles: la Capa de Presentación (lo visual en el navegador), la Capa Lógica o de Negocio (las funciones del sistema) y la Capa de Datos (la base de datos).

  • Ventaja: Cada parte del equipo trabaja en su propia capa de forma ordenada.
  • Desafío: Obliga a mantener reglas estrictas de conexión entre capas.
Ejemplo: Sistemas académicos universitarios o bancos
En la Nube

Serverless (FaaS)

El desarrollador solo se encarga de programar las funciones de su aplicación; el proveedor en la nube administra los servidores y recursos sin que el programador deba preocuparse por ellos.

  • Ventaja: Solo pagas por los segundos exactos que tu código se ejecuta.
  • Desafío: Es difícil mudar el código a otro proveedor si decides cambiar de servicio.
Ejemplo: Procesamiento de pagos con Stripe o redimensionar fotos subidas
